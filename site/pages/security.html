Security

The parts that usually worry a security review

Alicorn's architecture removes most of them by construction: the expensive, sensitive work happens on your own machines, and the control plane stores decisions rather than code.

What we never have

Your model keys

Agents authenticate with each employee's own subscription, on their own machine. Alicorn holds no provider credentials.

Your source code

Execution, worktrees and builds stay on the client. The control plane stores decisions and metadata, not repositories.

A hosted execution fleet

There is no shared runner your code passes through, because there is no runner at all.

Controls

ControlHow
Tenant isolationEnforced by row-level security in the database, not by application query filters. A bad query cannot cross the boundary.
IdentityOIDC with PKCE against Keycloak, self-hosted alongside the rest. SSO, SAML, LDAP/AD federation and SCIM provisioning.
Blast-radius budgetsFiles, spend and protected paths capped per run — not per task, so splitting work cannot launder past the limit.
No self-judgingThe required checks a stage verifies against are authored on the stage. A member cannot loosen the criteria it is judged by.
Standing exceptions expireDisabling a gate requires a named author and a mandatory expiry, and stays visible in the audit view until it lapses.
Immutable trailThe ledger is append-only and exactly-once. Duplicate deliveries are absorbed; timestamps are server-assigned.
Supply chainSigned container images, published SBOM per release, distroless non-root runtime, dependency and image scanning in CI.
Data residencySelf-hosted by default. Nothing leaves the infrastructure you run it on.

Reporting a vulnerability

If you believe you have found a security issue, email security@alicorn.dev with steps to reproduce. We acknowledge within one business day and will keep you updated until it is resolved. Please do not open a public issue.
