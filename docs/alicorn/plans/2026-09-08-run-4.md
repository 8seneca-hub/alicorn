## Process — two rules learned the hard way in run 3

**Never `git reset --soft main` to squash a rebased branch.** GP3 was rebased onto BR1, MR1 merged, then
the soft reset took `main`'s _new_ position as the parent while keeping GP3's _old_ tree. Git recorded
the difference as deletions: **10 of MR1's files removed and 10 more reverted**, in a commit that
fast-forwarded cleanly and typechecked. It was caught only by explicitly checking that MR1's files still
existed after the merge. Squash with `git reset --soft <the rebase base>`, or rebuild from the branch's
true diff.

**A green merge is not evidence the merge is correct.** Add to the merge protocol: after merging a
branch that was rebased before another branch landed, verify the earlier branch's files are still
present. Cheap, and it is the only thing that caught the above.

Still standing from run 2, and validated twice more: **commit early**. Run 3 was interrupted twice — a
network outage and a rate limit — and lost nothing, because every agent had 5–8 WIP commits. The run
that lost four tickets had none.
