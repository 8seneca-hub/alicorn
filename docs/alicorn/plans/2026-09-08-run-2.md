## 5. One process change, earned the hard way

**Audit before dispatching.** Three of six run-1 tickets were substantially already built. Each cost a
full agent — roughly 150–200k tokens — to rediscover finished work. Before run 3, spend ten minutes
checking each candidate against the tree: `git log --oneline -20 -- <the ticket's main file>` and one
`rg` for the symbol it proposes to add. Cheaper than any of the alternatives.

The related rule from run 1: **a ticket's own text goes stale.** LG3 still says "v33 migration" when
`SCHEMA_VERSION` is 37; LG4's scope listed four items that were already merged; L1 says eight locale
catalogs and there are six. Trust the tree, not the ticket.

## 6. Setup

Reserved and already in place: databases `alicorn_test_c1/c2/c3`; migration numbers **v38–v40 still
unallocated** (`SCHEMA_VERSION` is 37 — claim on `main` before writing one).

```sh
git worktree add ../orca-wt/<branch> -b <branch> main
cd ../orca-wt/<branch>
corepack pnpm install --frozen-lockfile     # NOT bare `pnpm install` — see LOCAL-DEV.md
```

Cloud branches also need their own shim and slot:

```sh
mkdir -p cloud/.pnpm-shim
corepack enable --install-directory "$PWD/cloud/.pnpm-shim" pnpm
export PATH="$PWD/cloud/.pnpm-shim:$PATH"
export ALICORN_TEST_POSTGRES_URL="postgres://postgres:postgres@127.0.0.1:5433/alicorn_test_c1"
cd cloud && pnpm install && pnpm -r build
```

`pnpm -r build` before typecheck or test — the apps import the packages' `dist`. And check the run
count, not the colour: the Postgres suites skip silently and still exit 0.
