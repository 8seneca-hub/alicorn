### Four repairs, and what they say about the process

- `main` was red at typecheck for one commit: AT1 and CR2 each broke the other's fixture, I fixed it
  in the worktree, verified green, and merged the commit that did not contain the fix. **Verifying and
  committing are not the same act** — check `git status` before every merge.
- AT1 added a bare `orca` call site to the skill corpus and never regenerated the bundled copy, and I
  merged it without running the corpus gates. **The changed-code quality gate is not the gate set.**
- Fixing that exposed a real defect in `verify:rebrand-cli-gate`: it keyed findings on the whole
  _line_, and `bundled-skill-guides.ts` holds each guide as one single-line string, so editing any
  guide reported a brand-new call site. Same false positive R6 removed one level down. Now keyed on
  the invocation — and the honest count is **486 call sites, not 329**, because a line with three
  invocations only ever counted once.
- The runtime portability ratchet was red: I4's Keycloak path pulled `electron.app` and
  `electron.safeStorage` into the runtime graph, which breaks orcad's plain-Node boot. Routed through
  the `AppEnvironment` and `SecretStore` host ports the repo already had.

**Process change, earned:** before merging any branch, run the full gate sweep, not just
`check:code-quality:changed`. The four gates that matter and are cheap: `verify:rebrand-cli-gate`,
`verify:bundled-skill-guides`, `verify:skill-bundle-manifest`, `check:runtime-electron-ratchet`.
