### Slot 1 — R5a, in detail

`orca-dev` is not a leftover string: it is `config/scripts/orca-dev.mjs`, a `/usr/local/bin` symlink,
and the command the app's own agent preambles select in dev mode. Renaming it touches the shim, the
launcher that picks it, three skill guides and the generated `src/cli/bundled-skill-guides.ts`.

- Keep an `orca-dev` alias for one release, the same posture R2 took for the production binary — a
  developer with the old symlink on `PATH` must not get a "command not found" mid-session.
- The alias is *dev-only*, so it never reaches a user's machine; it can retire on a much shorter
  clock than the production shim's.
- Finish with `verify:rebrand-cli-gate` at **baseline 0**, and delete the baseline's rows rather than
  allowlisting the guides — run 6 and run 7 both paid for that lesson already.

### Slot 3 — why Task 8 now and not with R4

Run 7 bumped the hook protocol to v2 so that an endpoint file written under the old name reads as
outdated. That is a *signal with no receiver*: nothing sweeps hosts, so a WSL distro or SSH host
still holding a v1 hook stays silent — which is precisely ROADMAP's *Stale hooks after the env
rename* risk, now live on `main` rather than hypothetical. Its spec is written
([rebrand plan, Task 8](./2026-09-06-rebrand-cutover-distribution.md)) and its model
(`ssh-relay-versioned-install.ts`) exists.

The rule that matters here: **loss of contact is never evidence of anything.** An unreachable host is
reported `unreachable` with a reason, never assumed current and never assumed dead.

## Departure from the parallel-worktree plan: this run is sequential

Runs 3–7 fanned out across worktrees with a subagent per ticket. This run does not — the session
executing it is not permitted to dispatch subagents, so the slots run one at a time in the order
above. Two consequences, worth stating rather than discovering:

- **Slots 1 → 2 are a hard chain** (the cut cannot precede the baseline it asserts), and 3, 4, 5 are
  independent of both, so a sequential order costs nothing but wall clock.
- **The parallel plan's rebase discipline still applies in miniature**: each slot rebases onto `main`
  before merging, and `pnpm test config/scripts` runs in full before each merge. Run 7's triage rule
  is now standing practice: *a failing-test count is not a verdict — diff the failing file set
  against `main` before believing it.*

## Slot 5 as built — branch triage

Three branches sat ahead of `main`. Two were provably superseded and are deleted:

- **`alc-61-foreman-journal`** — `coordinator-foreman-journal.ts` and `journal-writer.ts` are both on
  `main`; FJ1 landed the journal in a different shape.
- **`alc-92-code-stages-closeout`** — two of its four commits matched by patch-id, and the other
  two's artifacts (`code-stage-outcome-enqueue.ts`, `code-stage-runner.ts`, the CLAUDE.md paragraph)
  are on `main`.

**`8seneca-global/multi-repo` is not superseded, and is now its own decision (ALC-117).** It carries
a *second implementation of the Contract Registry*: `main` keeps it in the run's Foreman journal on
disk, where it is rewritten in place and dies with the run; the branch puts it in the Control API on
Postgres as mutable versioned configuration. Both files open by insisting they are the Contract
Registry and never a "contract ledger" — one concept, two homes, opposite retention. The branch also
holds contract extraction, a contract check runner, a composed verification runner and the CLI's
task-repos handler, ~3.7k insertions across 62 files.

It reads as landed at a glance because `main` does have the *acknowledgement* half (CR2). That is
what made `git cherry` insufficient here: four of five commits report as not-upstream while the
feature they belong to is partly present under different paths. **Patch-id is not a verdict on a
rebased fork; check the artifacts.**

Recommendation recorded on the ticket: keep `main`'s, because CLAUDE.md puts Foreman state on disk
and the Control API's three jobs do not include a per-run interface registry.
