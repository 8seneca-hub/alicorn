### Slot 1 — R5a, in detail

`orca-dev` is not a leftover string: it is `config/scripts/orca-dev.mjs`, a `/usr/local/bin` symlink,
and the command the app's own agent preambles select in dev mode. Renaming it touches the shim, the
launcher that picks it, three skill guides and the generated `src/cli/bundled-skill-guides.ts`.

- Keep an `orca-dev` alias for one release, the same posture R2 took for the production binary — a
  developer with the old symlink on `PATH` must not get a "command not found" mid-session.
- The alias is *dev-only*, so it never reaches a user's machine; it can retire on a much shorter
  clock than the production shim's.
- Finish with `verify:rebrand-cli-gate` at **baseline 0**, and delete the baseline's rows rather than
  allowlisting the guides — run 6 and run 7 both paid for that lesson already.

### Slot 3 — why Task 8 now and not with R4

Run 7 bumped the hook protocol to v2 so that an endpoint file written under the old name reads as
outdated. That is a *signal with no receiver*: nothing sweeps hosts, so a WSL distro or SSH host
still holding a v1 hook stays silent — which is precisely ROADMAP's *Stale hooks after the env
rename* risk, now live on `main` rather than hypothetical. Its spec is written
([rebrand plan, Task 8](./2026-09-06-rebrand-cutover-distribution.md)) and its model
(`ssh-relay-versioned-install.ts`) exists.

The rule that matters here: **loss of contact is never evidence of anything.** An unreachable host is
reported `unreachable` with a reason, never assumed current and never assumed dead.

## Departure from the parallel-worktree plan: this run is sequential

Runs 3–7 fanned out across worktrees with a subagent per ticket. This run does not — the session
executing it is not permitted to dispatch subagents, so the slots run one at a time in the order
above. Two consequences, worth stating rather than discovering:

- **Slots 1 → 2 are a hard chain** (the cut cannot precede the baseline it asserts), and 3, 4, 5 are
  independent of both, so a sequential order costs nothing but wall clock.
- **The parallel plan's rebase discipline still applies in miniature**: each slot rebases onto `main`
  before merging, and `pnpm test config/scripts` runs in full before each merge. Run 7's triage rule
  is now standing practice: *a failing-test count is not a verdict — diff the failing file set
  against `main` before believing it.*

## Slot 3 as built so far — R4 Task 8, first half

On `alc-r4-task8-hook-sweep`: `5d1d0b5e5` then `1d2209141`, **not merged**, because a guard rail
ships with the feature that needs it and this one is not wired yet.

**The ticket's premise was wrong, and correcting it made the work smaller.** Task 8 assumed the v2
protocol bump makes a stale hook detectable, and that the sweep therefore needs to probe a version.
It does not: a managed script posts `version=%ALICORN_AGENT_HOOK_VERSION%`, read from the endpoint
file *at invocation*, and that file now carries both env spellings — so a pre-rename script reports
v2 exactly like a current one. The bump made a stale *endpoint file* detectable, never a stale
*script*.

What does detect it was already there. `writeManagedScript`, `writeManagedScriptRemote` and
`refreshManagedScriptIfPresent` each read the installed script and compare it byte-for-byte against
what this build would write, then skip when identical — and a v1 script's bytes differ, because it
reads the old env names. All three were discarding that answer. The first two now return
`'written' | 'unchanged'`, and `sweepHookReinstall` consumes it: no marker, no version, no second
source of truth to drift, and it catches *any* drift rather than only a bump someone remembered.

The verdict vocabulary is the part worth keeping: `unreachable` carries its reason and never stands
in for `current`, because loss of contact is not evidence that anything is installed.

### As wired

**The collector, not the widened boolean.** `recordManagedScriptWritesDuring` scopes a log to one
host's install and the three writers report into it. `refreshManagedScriptIfPresent` keeps its
boolean exactly as it is: that `true` means *present*, and fourteen call sites across thirteen
files read it that way — widening it to a union would invert every one of them silently, because
`'absent'` is a truthy string. The log is not re-entrant and throws on a nested call rather than
attributing one host's writes to another.

**Startup sweeps the local host only.** Dialling every configured SSH host on every launch is a
startup cost nobody asked for, so remote hosts are reported on their own connect path, where the
install already happens — WSL through `wsl-hook-fs-adapter`, which now names the distro when it
replaces an outdated script or cannot reach one.

What is deliberately not done: the SSH client half. Its hooks install through the relay running on
the remote host (`managed-hook-runtime.ts` installs to that host's *own* filesystem), so the sweep
belongs there rather than in the client, and that is a separate seam from the two wired here.
